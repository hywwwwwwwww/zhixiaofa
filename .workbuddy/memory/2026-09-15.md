### 补充修复：输入框固定不生效（整页滚动）

现象：消息变多后输入框被顶到文档最底部，必须滚动才能看到。
原因：`.zf-app` 只有 `min-height: 100vh`、没有确定高度，高度由内容撑开 → `.zf-content--chat` 的 `flex:1` 拿不到确定高度 → `.zf-chat` 随内容变高 → 整页滚动，`#chat-body` 内部滚动失效。
修复（`css/app.css`）：问答页给应用壳加 `.zf-app--chat { height: 100vh; height: 100dvh; overflow: hidden; }`（先用 vh 兜底、再用 dvh 兼容移动端地址栏），`.zf-content--chat` 补 `min-height: 0`，`.zf-chat__head` / `.zf-chat__foot` 设 `flex: 0 0 auto`（只有 `.zf-chat__body` 可收缩），`zf-chat__foot` 再加 `position: sticky; bottom: 0` 作兜底；`pages/qa.html` 的外层改为 `class="zf-app zf-app--chat"`。
结论：聊天类页面必须让应用壳有确定高度（100dvh），否则 flex 高度链在 `min-height` 处断开。后续做类似"固定输入框"的页面照此处理。

## court.html（AI 小法庭）推演结果加图表

需求：推演结果里加「结果分布」扇形图 + 「赔付金额概率分布」折线/柱状图。

后端只有 `winProbability` / `compensationMin` / `compensationMax` / `similarCount`，没有分布字段，**未改后端**，分布在前端按可解释规则派生：

- 结果分布（环形图）：`完全胜诉 = p×0.55`、`部分胜诉 = p − 完全胜诉`、`败诉 = 100 − 前两者`，三者恒为 100%。配色 `['#4285f4','#fbbc05','#c9ced6']`，环心用 ECharts `title` 显示「胜诉 p%」，图例 formatter 带出百分比（不悬浮也能读数）。
- 金额分布（柱 + 累计折线，单 y 轴 0~100%）：把 `[min,max]` 等分 6 段，按钟形 `exp(-d²/(2σ²))`（σ=1.25，中值最高）赋概率，再算累计概率；金额口径整张图统一（`max>=10000` 用「万」，否则千分位元）。四舍五入零头补到概率最高段，累计末值强制 100%。
- 社保类案件 `compensationMax=0` → 显示空态「该类型案件通常支持补缴社保而非金钱赔偿」。

实现要点（`pages/court.html`，已引入 `../vendor/echarts/echarts.min.js`）：
- `chartsHtml(c)` 产出容器（id 带自增序号 `court-pie-N`/`court-bar-N`，因为结果卡和历史详情会同时存在多个实例）；`mountCharts(scope,c)` 按 id 前缀判断画哪张图。
- **必须先 `$('#result-card').show()` 再 `mountCharts`**，否则容器宽度为 0，ECharts 画不出来。
- `disposeCharts()` + `echarts.getInstanceByDom` 防重复渲染泄漏；`charts` 数组 + `isDisposed()` 过滤，窗口 resize 时统一 `resize()`。
- 顺带修了历史详情展开的 bug：原来用 `ZF.renderLoading` 替换整个 `.zf-list__main`（标题被冲掉、加载中文字残留），改为插入占位节点再替换内容。
- `css/app.css` 新增通用 `.zf-chart` / `.zf-chart__title` / `.zf-chart__hint` / `.zf-chart__box` / `.zf-chart__empty`。
