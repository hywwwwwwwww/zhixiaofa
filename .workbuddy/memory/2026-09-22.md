## 二、发现并修掉一个「分类会被自动同步刷坏」的真实风险

### 2.1 问题
导入后的 `source` 分布是 **`flk_npc` 524 / `doc_import` 219 —— 没有任何 `manual` 行**。
而我在 09-21 给 `upsert` 加的保护规则是：
```sql
category = IF(source = 'manual', category, VALUES(category))
```
**只保护 manual** → 现在 743 条全都不受保护。`LawSyncScheduleListener` 每天 **03:00**
会自动同步 15 部法律，把命中 (law_name, article_no) 的行按它的**粗分类**重写 category
→ 会再次出现「分类变少 / 分布失真」。

### 2.2 修法（改成按"分类是否为空"判断）
```sql
category = IF(category IS NULL OR category = '', VALUES(category), category)
```
语义：**已有分类一律保留，仅在原分类为空时才由同步补写**。
（比按 `source` 白名单更稳：将来出现新的来源标识也不会失效。）

  `quiz: id/difficulty`、`logs: id/costMs/createdAt`
- `laws.html` / `doc-templates.html` 的表格**没有 sortable 列**，无需实现

### 5.3 ★★踩坑：`copy2` 保留 mtime → Maven **静默跳过编译**（"假编译"）
第一次移植后实测**排序仍然无效**。用 MySQL 通用日志抓到真实 SQL：
```
SELECT * FROM sys_user WHERE 1=1 ORDER BY id DESC LIMIT 0, 4     ← 传了 asc 却是 DESC
```
逐层排除（Servlet/Service/Dao/SqlBuilder 代码链路都对、`getParameter` 会回落查询串）后，
**查 `.class` 内容**才真相大白：
```
SqlBuilder.class      {'orderBy': False, 'ORDER BY': False}  ✗ 缺新代码

```
原因：`shutil.copy2()` **会保留源文件的 mtime**（源项目文件是 09-21 17:29），
比目标目录里已有的 `.class`（09-22 19:33）**还旧** →
**maven-compiler-plugin 判定"源码没变"，直接跳过编译**，而 `mvn` 输出仍是 `BUILD SUCCESS`
（没有 "Compiling …" 那一行，但我上一轮没逐行看）。
⇒ **规矩**：复制过来的源码必须 `os.utime(fp, (now, now))` 刷 mtime 再编译；
  **并且必须核验 `.class` 内容**（搜关键字符串），**不能只看 BUILD SUCCESS**。

顺带把**所有历史移植功能**的 `.class` 都核验了一遍（10 项全绿：
排序 SqlBuilder/UserServlet/SysUserDaoImpl、法条同步 LawSyncService/监听器/Servlet、

## 六、管理员登录后直达后台（按角色分流）+ 核实后台无用户端功能

用户要求：「管理账号登录后就是进入到后台管理，而不是和个人用户一致的界面；管理端不需要有用户端的功能」。

### 6.1 定位：3 处跳转都不区分角色
| 位置 | 原逻辑 |
|---|---|
| `index.html`（根入口） | `user ? pages/home.html : login.html` |
| `login.html` **登录成功后** | `ZF.redirectLogin()` → 实际由登录页的"已登录"分支落到 `pages/home.html` |
| `login.html` **已登录则进首页** | `window.location.href = CTX + '/pages/home.html'` ← **管理员也被送前台** |

⇒ 管理员登录 → 落到前台首页 → 就是他说的"和个人用户一致的界面"。

### 6.2 改法：`common.js` 新增两个角色化跳转方法
```js
/** 登录后的落点：管理员进后台管理，普通用户进前台首页 */
ZF.homeFor = function (user) {
  return CTX + (user && user.role === 'ADMIN' ? '/admin/index.html' : '/pages/home.html');
};
/** 登录/注册成功后：优先回 zf_redirect（被守卫拦下的原页），否则按角色进对应首页 */
ZF.goAfterLogin = function (user) { ... target || ZF.homeFor(user) ... };
```
接线 4 处：`index.html` 根入口 1 处 + `login.html` 的「登录成功」「注册成功」「已登录」3 处。
（`ZF.post('/auth/login')` 的 resolve 值就是用户对象，所以能拿到 `role`。）

## 9. 参考 Art Design Pro 的布局思想与动画交互

用户给了 `https://www.app.artd.pro/#/dashboard/analytics`，要求参考其**布局思想**与**动画交互**。

### 9.1 怎么拿到参考（这一步本身值得记）
- 直接抓 URL 只拿到**登录页**（SPA + 滑块验证码，自动化登录不现实）。
- 该站是开源项目 **`Daymychen/art-design-pro`** 的 Pro 版 → **直接读 GitHub 源码**，比看截图猜准得多。
- `raw.githubusercontent.com` 在本环境 **SSL 握手超时**；改用 **GitHub contents API + `Accept: application/vnd.github.raw`** 取文件内容（`api.github.com` 可通）。
- Pro 版的 `dashboard/analytics` 不在开源版里；开源版对应的是 `src/views/dashboard/analysis/`（`modules/` 下 8 个模块）。

### 9.2 提取到的设计要点
**布局**
- **异构栅格**：每行 24 格用 `14/10`、`10/7/7` 这类**不等分**组合，靠宽度差建立主次（不是一律等分）。
- **卡片内嵌子卡片**：一张大卡里放 N 个小卡（`border + rounded-xl`，图标在上 / 数值 / 标签 / 上下文竖排居中）。
- **两种盒模**：`border-mode`（只有边框）/ `shadow-mode`（**双层阴影** `0 1px 3px rgba(0,0,0,.03), 0 1px 2px -1px rgba(0,0,0,.08)`）。
**动画**
- `ArtCountTo` 数字滚动：`useTransition` + **`easeOutExpo`** + 默认 2000ms + `tabular-nums`。
- `router-transition`：0.25s / 位移 15px / `cubic-bezier(.25,.1,.25,1)`，**离场比入场快（乘 0.7）**。
- 主题切换：View Transitions API 的 `clip-path: circle()` 从点击点扩散。
- `@keyframes breathe`：徽章 1.5s 缩放 + 透明度循环。
- 顶部 NProgress 进度条。

### 9.3 在本项目落地的（ES5 + jQuery 等价实现）
| 移植项 | 实现位置 |
|---|---|
| **数字滚动** | `js/common.js` 新增 `ZF.countTo(el, target, opts)`：requestAnimationFrame + easeOutExpo + 千分位，同元素重复调用先取消上一次 |
| **顶部进度条** | `admin/admin-common.js` 新增 `ZF.adminProgress.start()/done()`；接在侧栏导航点击上（只做**真实的等待反馈**，不伪造「进入时扫一遍」） |
| **入场过渡** | `app.css`：`.zf-content` 的 `zfPageIn`（0.28s / 位移 10px）+ 指标卡 `zfStatIn` 逐张 stagger（40ms 递增到 400ms） |
| **图表动画** | index / quiz / logs 共 7 处 `setOption` 统一注入 `animationDuration: 900` / `animationEasing: cubicOut` / `animationDelay: idx*30` |
| **双层阴影** | 管理端数据卡改 Art 的双层阴影 |
| **异构栅格** | 数据看板两处 `zf-grid--ratio-14-10`（文章 Top10 标题远长于法条号）/ `zf-grid--ratio-10-14`（慢接口的 y 轴标签是完整 URI，最需宽度） |

### 9.4 踩的坑（已入 MEMORY.md）
1. **`animation-fill-mode: both` 会把最终帧的 `transform` 留下来，单位矩阵 `matrix(1,0,0,1,0,0)` 也照样创建 containing block**。
   实测 `.zf-content` 加了 `both` 后，动画结束的 computed transform 是单位矩阵而非 `none` ——
   这会让它成为后代 `position:fixed` 的包含块（本项目内容区当前没有 fixed 元素，属隐患非现症）。
   修法：**delay 为 0 的入场动画不要加 fill-mode**（播完回到元素自身样式）；
   **有 delay 的（指标卡 stagger）必须留 `both`**，否则 delay 期间元素会先显示再跳成透明、闪一下 ——
   代价是保留单位矩阵，需确认其内部不会有 fixed 元素。
