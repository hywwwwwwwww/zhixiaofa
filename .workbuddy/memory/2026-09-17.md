## 2026-09-17 · 首页「使用概览」指标卡尺寸优化

### 用户诉求
截图框选首页顶部 4 张指标卡，说「这个框起来的地方大小有点问题」。
未指明具体问题，因此先做实测再定性。

### 实测（改造前，app.css 未改）
- 卡片 270.8×168.9px（1440×900），但内容只有「42px 图标 + 45px 宽文字块」
- 竖向：内容约占卡片高度 1/4
- 横向：内容 45px / 可用 230.8px（19.5%）；1920 下 45px / 350.8px（12.8%）
- `.zf-stat__go` 离右边框只剩 **1px**（几乎贴边）
- 「审查合同」用 `bi-file-earmark-check`，与「生成文书」的 `bi-pencil-square`
  在 42px 下都是「方块套勾/笔」，缩略分辨不出

用户选择：**加大内部元素并让内容铺开** + **只改首页这一处**。

### 本轮的真正根因（走了两条弯路，值得记）
**`.zf-card` 是 `display:flex; flex-direction:column`，`.zf-stat` 只重写
`display:flex` 没重置方向 → 继承了 `column`。**

由此派生的三个症状，单看 CSS 一个都看不出来：

1. **`.zf-stat__go` 用 `margin-left:auto` 定位**（为横向 flex 设计）。
   在 `column` 下 `margin-left:auto` 左右都生效 → 箭头水平居中而不是贴右。
2. **`align-items:center`** 让图标按自身宽度居中，而文字块被撑满后左对齐
   → 两者中线对不齐，截图里是「图标悬在文字左上方」的怪异观感。
3. 弯路一：只写 `.zf-stat > div { flex:1 1 auto }` → 实测图标左缘距内容区
   左缘 **87.4px**（卡片才 270.8px 宽）。
   弯路二：改 `flex-wrap:wrap` + 箭头 `flex-basis:100%` 逼换行 → 箭头确实换行了，
   但 `flex-wrap` 改变交叉轴语义，图标从 52px 被**横向拉伸到 105.4px**。

**最终方案：直接上 CSS Grid**，四个方向全显式声明：
```css
.zf-content--home #stat-grid .zf-stat {
  display: grid;
  grid-template-columns: 52px minmax(0, 1fr);
  grid-template-rows: auto auto;
  justify-content: start;   /* 必须写，否则继承 align-items 把内容整体居中 */
  align-items: center;
  column-gap: 14px; row-gap: 10px;
  padding: 20px 22px;
}
/* 图标 row1/col1、文字块 row1/col2、箭头 row2 跨两列靠右 */
```

### 最隐蔽的一个坑（差点没查出来）
```css
.zf-content--home #stat-grid .zf-stat > div { grid-area: 1 / 2 / 2 / 3; }
```
**图标本身就是 `<div class="zf-stat__icon">`，同样命中这条选择器！**
它的特异性 (0,2,1) 高于图标规则 (0,2,0)，于是把图标的 grid-area 也改写成
第 2 列 —— 图标和文字块挤在同一格。

排查手法（重要）：光读 CSS 完全看不出来，必须读 **computed `gridArea`**：
- 症状：图标 `gridArea` 是 `1 / 2 / 2 / 3` 而不是我写的 `1 / 1 / 2 / 2`
- 决定性实验：用**内联样式**（最高特异性）设 `grid-area: 1/1/2/2`，
  实测 `iconOff` 从 67px 变成 1px → 证明「布局逻辑对，是我的规则在层叠中输了」
- 修法：`> div:not(.zf-stat__icon)`

### 另一个必须显式声明的属性
grid 容器不写 `justify-content` 时，`.zf-stat` 上的 `align-items:center`
（通用规则第 132 行）会被继承进 grid 容器的 place-items，
把**整个格栅内容**居中 —— 实测图标左缘被推到距内容区左缘 67px。

### 「页面变高了吗」的归因（自己给自己做 A/B）
初期探针没记录 `docH`，导致无法判断「滚动」是不是我引入的。
补做 `diag-attribution.js`：页面加载后用注入样式把被我改的属性**逐条还原**成
通用档位，再读 docH：

| | 改造后 | 还原后 |
|---|---|---|
| 网格高 | 125px | 167.8px |
| 页面高 | 1220 | 1262 |
| 是否滚动 | true | **true** |

结论：**首页本来就滚动**（有 5 张功能卡 + 4 条问答 + 5 篇文章），
本次改动反而让页面**矮了 42px**。因此断言从「无纵向滚动」改成

### 踩坑
1. **【本轮最大的坑】`.zf-list__item` 是 `display:flex`（row 方向），
   展开区作为「第 3 个 flex 子元素」被排到了 main 的右边**，
   等于凭空加了一列 → `.zf-list__main` 的 `flex:1` 被压到几乎没宽度，
   标题**变成一个汉字一行**（竖排）。
   修法：`.zf-list__item { flex-wrap: wrap }` + `.zf-home-detail { flex: 0 0 100% }`。
   **不能用 `flex-direction:column`** —— 那会把 meta（时间+徽标）从右侧挪到下面，
   与不带展开区的文章列表版面不一致。
   —— 这个 bug 读 CSS 看不出来，**必须看截图**（101-home-qa-open.png 里最明显）
2. **`cdp.js` 的 `httpGet(url)` 只接受完整 URL**，不是 `(port, path)`。
   传 `(port, path)` 时 Node 把数字当 URL，静默回落到 `127.0.0.1:80`
   → `ECONNREFUSED`，报错信息里完全看不出是参数写错。
3. **`cdp.connect` 返回 `{send, socket}`，没有暴露 message 事件订阅**。
   别自己 `socket.on('message')` 过滤 id —— `send` 本身就返回按 id 匹配的 Promise。
4. **本环境 bash shim 缺 coreutils，node 脚本被 SIGTERM 时看不到任何输出**。
   新建 `runnode.py`（Python subprocess 包装）才能拿到真实 returncode 与 stdout。
5. **弹窗遮罩「看起来没生效」是截图时序假象**：实测 `.modal-backdrop`
   确实已插入且 `opacity:0.5`、`z-index:1050`、`body.modal-open` 已加。
   Bootstrap 的 .15s 过渡 + headless 合成需要时间，截图要等 1.5s 以上。
   —— 差点为一个没坏的东西改代码。

### 本轮最硬的三个根因（读 CSS 都看不出来，全靠实测）

**1. `--zf-ink-3` 对比度全线不达标**
`#7f8d9f` 在白底 **3.38**、侧栏 `#f0f6ff` 底 **3.11**、`#eff1f4` 底 **2.99**、
`#f7f8fa` 底 3.18 —— 全部 < AA 4.5。
改 `#5f6b7a` → 白底 **5.43** / 侧栏 **4.99** / muted **4.79**。
另新增 `--zf-ink-4:#8a94a3` 只给装饰/禁用，不承载正文。

**2. 首屏溢出 18px 的魔数 `calc(100vh - 106px)`**
`.zf-desk__result` 的 min/max-height 写死 `100vh-106`，而它上方真实偏移
= topbar 68 + `.zf-content` padding-top 22 = **90**（106 只算了「顶栏 + 一点余量」）。
修正为 **112** 后仍差 18px —— 因为 `.zf-content` 的 `padding-bottom` 是 **40px**，
而 112 的算式只按 22 算。**40 - 22 = 18**，与实测 court 918 - 900 完全吻合。
修法：`.zf-content` 默认 `padding-bottom` 40 → **20**，
`.zf-content--doc` / `.zf-content--profile` 反向覆盖回 40（这两页走 `.zf-work`，
面板锁在视口内、内容底边离视口底常有 200px 富余，需要 40 才有呼吸感）。
**court 924 → 900 精确达标**。

**3. contract 比 court 多 20px —— 因为 ≥900px 视口档根本没有压缩规则**
原有压缩档只有 `min-height:801~899` 与 `max-height:800` 两档，
**≥900px（1440×900 / 1920×1080 两个最主流桌面尺寸）完全没有压缩**。
而 `.zf-desk__result` 的 min-height = 视口高，等于要求左栏表单严格 ≤ 视口高。
contract 表单比 court 多「合同基本信息 + 当事人与签订时间」两段共 3 个分组，
每段都有一行小标题（19px）+ 字段组间距（11px）固定开销，累计顶出 20px。
**新增 `@media (min-height: 900px)` 档**，收 21px：
上传区分隔行 `margin 11/12 → 4/4`（省 9px，矮屏档本来就整行 `display:none`，
说明它确是纯装饰）+ 卡内 padding `20 → 16`（省 8px）+ 卡头 `margin-bottom 14 → 10`（省 4px）。
**contract 940 → 900 精确达标**。

### 本轮踩坑（新的，已补进 MEMORY.md）
- **file:// 下读不到 cssRules**：`document.styleSheets[i].cssRules` 全部抛
  `SecurityError: Cannot read the 'cssRules' property`（3 个表都中）。
  → 「CSS 规则是否存在」必须改用**计算值证明**，不能扫 CSSOM。
- **对比度探针 hex 未转 rgb**：`getPropertyValue('--zf-ink-3')` 返回 `#5f6b7a`，
  而 `lum()` 用 `c.match(/[\d.]+/g)` 只认 `rgb()` → 把 `5`/`6`/`7` 当 RGB 分量，
  算出 **1.04** 这种荒谬值。修法：先用临时元素让浏览器归一化。
- **`elementFromPoint` 判定不能双向 `contains`**：目标常嵌在可点的列表行里
  （`.zf-home-refs` 在 `.zf-home-item` 内），用 `t.contains(e)` 会把整行都算命中，
  **掩盖真实缺陷**（`.zf-quick__item` 无热区时也误判为通过）。
  只允许 `t===e || e.contains(t)`。
- **打点前必须逐个 `scrollIntoView`**：初版只滚第 1 个，2~4 号在视口外，
  `elementFromPoint` 返回 null → 误报成「热区缺失」。
- **`::after` 热区用 `height:100%` 无效**：行内元素的伪元素只能长到自身高度，
  `min-height:44` 被内容压住。必须 `top:50%;bottom:50%;left:50%;right:50%`
  + `margin:-22px`（`top/bottom` 已把盒子压成 0 高，`min-height` 由 margin 撑开）。
- **`Emulation.setEmulatedMedia({name:'hover'})` 不足以翻转 `(hover:none)`**：
  实测仍读到 44px。必须同时 `setTouchEmulationEnabled` + `mobile:true`。
- **鉴权桩的 XHR 是同步立即 resolve**：`then` 里 `stopRunning()` 跑得极快，
  260ms 观察窗口早已结算完 → 进行中态断言集体误报「不可见」。
  → 验收时临时 hook `XMLHttpRequest` 给 `send` 加 3~4s 延迟，才保得住中间态。
