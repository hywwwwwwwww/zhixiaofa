## 合同审查页（contract-review.html）增加文件上传解析

需求：原来只能粘贴文本，需要支持上传 docx / pdf 自动提取正文。

**技术选型：前端解析，不加后端接口。**
理由：`AuthFilter`/`JsonBodyFilter` 只映射 `/api/*`，项目没有 `@MultipartConfig`，也没有文件存储表（`contract` 表只存正文文本）；`docs/API接口文档.md` 里也没有上传接口约定。前端解析后走原有 `POST /api/contracts`，改动最小且和设计文档一致。项目已有 vendor 化第三方库的习惯（jquery/bootstrap/echarts/bootstrap-table）。

新增 vendor（从 cdnjs 下载，均可用）：
- `vendor/mammoth/mammoth.browser.min.js`（1.6.0，643KB）→ docx
- `vendor/pdfjs/pdf.min.js` + `pdf.worker.min.js`（3.11.174，320KB + 1.06MB）→ pdf。选 3.x 是因为 4.x 只有 ESM，不能直接用 `<script>` 引；worker 路径用 `ZF.CTX + '/vendor/pdfjs/pdf.worker.min.js'` 指向同版本本地文件。

实现要点：
- 上传区 `.zf-upload`（虚线框、hover/dragover 高亮、整块可点、支持拖拽），位于表单卡片顶部，下方用 `.zf-upload__divider` 分隔"或手动填写以下信息"。
- 解析：docx → `mammoth.extractRawText({arrayBuffer})`；pdf → `pdfjsLib.getDocument({data}).promise` 逐页 `getTextContent().items.map(it=>it.str).join('')`，页间空行分隔，最多 30 页（超出追加提示），解析完 `pdf.destroy()`；txt/md → `file.text()`。
- 校验：仅 `.docx/.pdf/.txt/.md`（不支持旧版 .doc），≤10MB；提取 <10 字判定为扫描件/加密文档并提示直接粘贴。
- 回填：写入 `#cf-content`，`#cf-name` 为空时用文件名（去扩展名）填充；正文已有内容时先 `ZF.confirm` 再覆盖。
- 状态：`.zf-upload__status` 三种态（loading 转圈 / ok 文件胶囊+字数+移除 / error 红字），成功再 toast。
- `css/app.css` 新增 `.zf-upload*` 一组样式。

**验证**：手工用 Node 生成了一个规范 docx（`Compress-Archive` 生成的是反斜杠路径的非法 OOXML，改用 `zlib.deflateRawSync` + 手写 ZIP local/central header + CRC32 构建），用下载的 mammoth 跑通解析，中文与段落空行均正确（120 字）。pdf 分支在本环境无法端到端验证（浏览器进程起不来），依赖 pdf.js 标准 API + 失败兜底提示。

## 左栏改 Tab 切换 + 右栏消除空白（3 个 subagent 出方案后合成）

用户反馈两点：① 右侧下栏还是有点空；② 左栏太长，希望上方有两个标签切换左栏内容。开了 3 个 subagent（Tab 信息架构 / 右栏空白填充 / Tab 组件 CSS+a11y 实现），三份方案结论一致，合成落地。

### 一、左栏 Tab 切换（`.zf-desk__panel` 包一层）

**语义切分**：两 Tab，按页定制文案 —— court 是「填写案情 / 推演记录」，contract 是「上传审查 / 合同档案」。否决三 Tab 方案（示例已有卡头按钮 + 右栏空态快捷按钮两个入口，重复；380px 窄栏三 Tab 横向拥挤）。

**结构**：新增 `.zf-desk__panel` 接管原来两块卡的栅格定位（`grid-column: 1; grid-row: 1 / span 2`），内部放 `.zf-tabs` + 两个 `role="tabpanel"` 卡片。**两页结构完全同构**，共用一套 CSS/JS。

**交互规则**：
- **草稿必须保留** → 切换只切 `hidden` 显隐，DOM 不销毁。特别注意 court 提交成功后虽有 `$form[0].reset()`，但切 Tab 绝不 reset。
- 点历史项载入右栏后**不自动切回**「填写」页签（用户还在浏览记录的心流里）。
- 历史为空**不禁用** Tab，只置灰列表空态（禁用会让人以为功能坏了）。
- **不做 localStorage 持久化**：contract 页已有 `#history` 锚点供首页指标卡跳转，再叠加 hash 会冲突。改为**只读不写**——`hash === '#history'` 时首次进入激活记录页签，并把 `id="history"` 从历史卡移到 `.zf-desk__panel` 外层（否则隐藏的 panel 上定位不到锚点）。
- 切到记录页签时若列表为空则补拉一次；`onChange` 里对 contract 页重跑 `ZF.handleHashAnchor()`（面板由隐变显后高度变了）。

### 二、右栏消除空白（方案 F+D+G 组合）

**关键诊断**：`position: sticky` **不会拉高元素**，所以"空"只有两种成因 —— ①右栏内容天然比左栏两行短（court 有结果时 ≈620px vs 左栏 ≈1130px）；②卡片白底被撑到视口底但内容只占上半（contract 只有 1-2 条风险时最严重，≈300px）。court 属①，contract 属②。

**核心修复（不是"填内容"，是把空白变成有结构的底栏）**：
```css
.zf-card { display: flex; flex-direction: column; }        /* ← 根因！见下 */
.zf-desk__result {
  display: flex; flex-direction: column;
  min-height: calc(100vh - 106px);   /* 420px → 视口高，卡片底边贴视口 */
  max-height: calc(100vh - 106px);
}
.zf-desk__result-body { flex: 1 1 auto; min-height: 0; overflow-y: auto; }
.zf-desk__result-foot { margin-top: auto; }   /* 操作条被推到底，吸收富余高度 */
```
- **踩到的坑**：`.zf-history__list { height: calc(100vh - 420px) }` 不生效，因为 `.zf-card` 原是块级元素、高度 auto → 子元素的百分比/`vh` 计算出后又被内容高度顶破。**必须把 `.zf-card` 改成纵向 flex 列**才能让"撑满剩余高度"成立。这个改动影响全站所有卡片的布局链，需要留意。
- **去掉 `min-height: 420px`**，否则会在 viewport < 526px 时产生 `min-height > max-height` 的非法组合（浏览器取 min-height 胜出，卡片溢出），而新链路已由 flex 保证高度。
- **占位卡也要吃满**：`#result-placeholder` 用 `min-height: 100% + flex column`，口径说明加 `margin-top: auto` 沉底，否则占位态中段上下都空。

**内容补充（D 口径透明化）**：court 新增 `renderOdometer(c)` —— 把环形图三档占比 + 6 段金额区间概率/累计概率落成 `.zf-metrics-table` 小表，既填高度又能核对"百分比从哪来"。**max 段用 `<strong>` 加粗**，与图表里"最可能落点"呼应。

**内容补充（B 后续行动）**：两页各加 `renderActions`。court 按胜诉概率分档（≥70 / 45-69 / <45）+ 证据整理 + 金额主张策略（有无金额分布时文案不同，社保类走"行为之诉"表述）+ 仲裁时效。contract 先按 `risks` 里有无 `high` 分档 + 保存原件 + 时效 + 慎重决策。

**底部操作条（G）**：`#result-foot` 两个按钮 —— 复制/再推演。court 走 `plainConclusion(c)`、contract 走 `plainReport(c)` 拼纯文本给 `ZF.copyText`；「再推演一次」= 切回「填写」页签 + `focus` 落到描述/正文框（比清空表单更贴合"改一改再推一次"）。占位态 `hidden`，并清空 `lastResult`。

**顺手修的两个问题**：
- contract 结果头部原来只有「风险徽标 + 共 N 个风险点」两个小元素，右栏很宽显得空 → 改成 `.zf-result-top` + 4 个 `.zf-metric`（整体等级/风险点总数/高·中·低构成/合同类型）。为此给 `.zf-result-top > .zf-result-metrics` 加 `flex: 1 1 100%`（court 的头部是「环形图 240px + 2 指标卡」，没有这个覆盖）。
- contract 风险条目原来按接口顺序展示 → 改 `riskWeight()` 排序把高风险排前面（`.slice()` 后再 sort，不原地改接口返回的数组）。

### 三、新公共组件：`ZF.tabs` + `ZF.tabCount`（common.js 末尾）

- **分段控件（胶囊）风格**，不用下划线 Tab：项目已有 `.zf-chips .zf-tag--active` 的胶囊选中语言，下划线会与 `.zf-card__head` 的 `border-bottom` 语义打架。
- 选项：`value`（初始选中）/ `preserve`（默认 true，只切显隐；false 则清空非活动面板）/ `onChange(name, prevName)`。返回 `{select, getValue, destroy}`。
- **不依赖 Bootstrap 的 `data-bs-toggle="tab"`**，自己写轻量实现，避免与其 JS bundle 行为耦合（jQuery 事件委托 + `off('.zftabs')` 命名空间）。
- 面板宿主由 tablist 最近的 `[data-panel-scope]` 祖先决定，未找到回退到父级。本项目的两页都把 tablist 与两个 panel 放在 `.zf-desk__panel` 内同层，所以不写 `data-panel-scope` 也能正确找到。
- **a11y**：`role="tablist"/"tab"/"tabpanel"` + `aria-controls` ↔ `aria-labelledby` 双向关联 + `aria-label` 组名；roving tabindex（整组只留一个 `tabindex="0"`）；`←/→/↑/↓` 循环 + `Home/End`，`preventDefault` 阻止页面横滚；「聚焦即选中」（项数少时比"聚焦后按 Enter"少一步）；禁用项 `aria-disabled="true"` 被键盘游走跳过；面板 `tabindex="-1"` 可编程聚焦但不占 Tab 序列；`[hidden]` 显式 `display:none` 兜底。
- `.zf-tabs__count` 徽标，选中态 `rgba(255,255,255,.24)` 底 + 白字，`ZF.tabCount()` 统一写入（`count<=0` / `null` / `NaN` 时 `hidden`）。`loadHistory` 的**非追加**分支里调用，保证删除后计数同步。

**验证**：①静态自检 7 页 —— 语法 0 错误、`$('#id')` 引用 0 缺失（剩余 warning 全是误报：`zf-tab-input`/`zf-panel-*` 是 id 不是类、`zf-danger`/`zf-primary-ink` 是 CSS 变量、`reject` 是 Promise 形参）；②`ZF.tabs` 行为自检 17 项全过（导出/roving tabindex/aria 同步/panel hidden/左右键循环/Home·End/onChange/preserve/禁用跳过/panel-scope 查找/同名静默早退/无 root 返回 null）+ `tabCount` 6 组边界 + 3 项键盘游走算法；③两页 `zf-content` 区块 div 嵌套平衡（逐层栈校验，`zf-desk__panel` depth 3 → 两个 panel depth 4，`result-card` depth 3 → body/foot depth 4）。浏览器仍无法在本环境启动，未做视觉验收。

顺手处理：`id="history"` 从历史卡**移到 `.zf-desk__panel` 外层**（否则面板 `hidden` 时 `getElementById` 拿到的元素不可见，`scrollToAnchor` 会定位异常），`ZF.handleHashAnchor()` 不用改。

```css
.zf-desk__history { display: flex; flex-direction: column; }
.zf-history__list { flex: 1 1 auto; overflow-y: auto; max-height: none; }
.zf-desk__history > #history-pager { flex: 0 0 auto; margin-top: auto; padding-top: 10px; }
```
但光这样不够——卡片本身高度还是由内容决定（auto），`flex: 1 1 auto` 没有富余空间可分配（这正是上一轮踩过的"父高 auto → 子元素百分比失效"的同类陷阱）。

**关键是让记录面板拿到一个确定高度**。用的手法：
```css
.zf-desk__panel { position: relative; }        /* 定位上下文 */
.zf-desk__input  { position: relative; z-index: 1; }   /* 盖在上面，高度完全由内容决定 */
.zf-desk__history { position: absolute; top: 0; right: 0; bottom: 0; left: 0; }  /* 撑满左栏总高 */
```
**推理链**（已用脚本按 1440×900 验算）：图表/推演报告只可能在右栏的 `#result-body` 里渲染 → 「填写」面板全高 = 内容高 = 结果卡高（右栏中唯一有内容的卡片）→ 左栏总高 = `max(填写面板高, 右栏两行高)`，因为结果卡是 `1 / span 2` 且 `min-height: calc(100vh - 106px)`，故左栏总高 = 结果卡高 = 视口高 − 106。于是 `left-over` 让记录面板正好补到左栏总高，**与右栏底边对齐**。

**为什么用 `left-over` 而不是 `height: 100%`**：`top/right/bottom/left` 是**定位属性**，参与 `left/top` 解析的容器高度**忽略绝对定位子元素**（CSS2.1 §10.1）——所以不会出现"记录面板把自己拉伸后反过来撑高左栏"的循环放大。这是这套手法的立身之本，误改成 `height: 100%` 就会退化成循环。

**两个必须同步的副作用**：
- 记录面板脱离文档流 → **必须给 `.zf-desk__input` 加 `position: relative; z-index: 1`**，否则记录面板（DOM 在后）会盖住表单。同时因为记录面板只在 Tab 切过去时才 `hidden` 解除，表单正常态本来就在上面，但显式声明更稳。
- `@media (max-width: 1100px)` 里**必须把 `.zf-desk__history` 改回 `position: static`**（单列下左栏不再与右栏并排，沿用绝对定位会把 Tab 面板高度压成 0），并把 `.zf-history__list` 改回 `max-height: 520px; flex: 0 1 auto`（单列下按内容自适应）。

**验算结果**：填写面板 1108→690px，记录面板 606→690px（+84px），列表可容纳约 11 条（改造前受 460px 限制约 9 条）。

### 一、【重要】列表塌陷的真正根因：position 与 display 是正交属性

**上一轮我判断错了。** 我以为是"单列断点忘了关 flex"，并在注释里写下「display:block 同时让 position 回到 static」——**这句话是错的**。`position` 与 `display` 互不相干，改 `display` 不会动 `position`。

真正的问题链：
1. 桌面链路 `.zf-desk__history` 用的是 left-over 绝对定位（`position:absolute; top/right/bottom/left:0`）
2. 1100px 断点里只写了 `.zf-desk__panel { position: static }` —— 那是**父元素**，不是 `.zf-desk__history` 本身
3. 于是断点下 `.zf-desk__history` 的 `position:absolute` **依然生效**，但它赖以定位的包含块（父元素）已变成 `static`，转而相对更外层定位 → 卡片脱离文档流、列表被推出可视区
4. 表现：卡片头正常、pager 的「加载更多」正常，**中间列表整个消失** —— 与截图完全吻合

**修法**：断点里对 `.zf-desk__history` 显式写全 `position: static` **加四个方位 auto**（缺一不可，只写 position 会残留偏移）：
```css
.zf-desk__history {
  position: static;
  top: auto; right: auto; bottom: auto; left: auto;
  display: flex; flex-direction: column;   /* 保留 flex：卡头与 pager 仍依赖 */
}
.zf-history__list { flex: 0 1 auto; min-height: 0; max-height: 520px; overflow-y: auto; }
.zf-desk__history > #history-pager { margin-top: 14px; padding-top: 0; }  /* 由 auto 改固定值 */
```
**不要改成 `display:block`**：卡片失去 flex 上下文后，卡头的 `flex:0 0 auto` 与 pager 的定位都失去依据。保留 flex、只把 pager 的 `margin-top` 从 `auto` 换成固定值，就能让「加载更多」落在列表下方。

**教训（比 bug 本身更重要）**：改 `position` 相关的布局时，**绝不能靠改 `display` 去"顺带"修**。定位属性必须显式改。另外上一轮我在注释里写下未经核实的断言（"display:block 同时让 position 回到 static"），这种错误注释会误导后续排查 —— **注释里的机制性断言必须验证过再写**。

## 【重大】列表不显示的真因定位 + 突破性获得真实浏览器实测能力

用户第三次反馈「合同档案 / 推演记录还是显示不出来」。调了 3 个 subagent 独立分析，**三个结论互相矛盾且全部错误**（甲：panel 塌成 0；乙：`margin-top:auto` 抢空间；丙：`display:none` 期间测量失效）。

### 前两次修复为什么无效（必须记住的教训）

前两次修复都写在 **`@media (max-width: 1100px)` 内部**，而用户在**桌面（>1100px）**使用 → **规则从未命中**。第一次加 `display:block`、第二次加 `position:static` + `flex-direction:column` + `max-height:520px` 全是空转。

> **教训**：修 bug 前先确认「用户实际所处的断点」，别默认用户在用窄屏。断点是条件分支，写错分支等号于没写。

### 真因（headless Edge 实测确认）

`.zf-desk` 有 `align-items: start` → `.zf-desk__panel` **不被拉伸**到栅格行高，高度只由**当前可见内容**决定：

1. 切到「合同档案」页签时 `#zf-panel-input` 被打上 `hidden`（`display:none`）
2. panel 里只剩页签行 → **panel 高度仅 54px**
3. `.zf-desk__history` 是 `position:absolute; top:0;bottom:0` → **也只有 54px**
4. 其内 `flex:1 1 auto` 的 `#history-list` 被算成 **0 高**
5. `overflow-y:auto` 把全部条目裁掉 → 「卡头与加载更多都在，列表一片空白」

**实测证据（1440×900）**：`panel h=54`、`panelHistory h=54 (scrollH=111 clientH=52)`、`historyList h=0 (scrollH=671 clientH=0)`、`historyPager top=161`（与列表 top 相同 → 压在列表上方）、`innerList h=671`（**内容确实在 DOM 里，是纯布局裁切**）。

### 修复（两处，均在全局层，不在任何 @media 内）

```css
/* 1) 关键：显式 align-self:stretch 覆盖 .zf-desk 的 align-items:start */
.zf-desk__panel {
  grid-column: 1; grid-row: 1 / span 2; min-width: 0;
  position: relative; align-self: stretch;   /* ← 新增 */
}
/* 2) 防御性兜底：即使 panel 再被塌掉，列表也保留最小可用高度 */
.zf-history__list { flex: 1 1 auto; min-height: 180px; overflow-y: auto; max-height: none; }
```

**修复后实测**：`panel 54→794`、`card 54→794`、`list 0→663`、`pager top 161→825`（从压在列表上变为在其下方）、8 条条目全部可见。

|---|---|---|---|

| 1920×1080 | 961 | 1080 | 已 OK |

### 【血泪坑 1】`rows` 会压过 `min-height`，前几轮的 textarea 高度设置全是死代码

`textarea` 高度 = **max(rows 撑出的高度, min-height)**。HTML 里 `rows="7"`，行高 1.65，实际渲染 **176px**。

而 CSS 里那三档 `min-height: 132px / 108px / 104px` —— **全部低于 176px，一条都没生效**。我在前几轮还以为"已经压到 132px 了"，其实从来没压下去过。

**修法**：① HTML 的 `rows` 从 7 改成 3；② 矮屏档不能用 `min-height`，要显式写 `height`（`height` 才能覆盖 rows 的固有高度）：
```css
.zf-desk__input textarea.zf-form-control { min-height: 96px; }          /* 全局 */
@media (max-height: 800px) {
  .zf-desk__input textarea.zf-form-control { min-height: 0; height: 76px; }   /* 必须写 height */
}
```

### 【血泪坑 2】断点上限写 760 导致整档永不命中（差 8px）

矮屏档原本写 `@media (max-height: 760px)`。但 **1366×768 的笔记本，浏览器 innerHeight 就是 768**，`768 > 760` → **整档永远不生效**。1280×800 同理。

**改为 `max-height: 800px`** 才能覆盖这两个主流尺寸。同理中档改成 `(min-height: 801px) and (max-height: 899px)` 与之无缝衔接、不重叠。

> 规则：按视口高度分档时，**上限要贴着"目标设备的最大 innerHeight"取值**，别按"屏幕标称高度"拍脑袋写。

### 【血泪坑 3】吸底条是坏方案，已删除

原先矮屏档给操作条加 `position: sticky; bottom: 0` 让按钮常驻视口底部。**截图实测发现它会盖住「保留完整条款文本 / 已输入 N 字」那行提示** —— 因为内容只比视口高一点点时，吸底条正好压在提示行上。比"需要滚一下"更难看，`scroll-padding-bottom` 也止不住。

**删除吸底条**，改为老实压缩内容高度。结论：
> **优先用「压缩内容高度」把按钮拉进首屏，不要用「吸底条」把它钉在首屏。** 吸底只适合内容远超一屏、压缩无法解决的情况。

### 最终压缩清单（矮屏档，累计省出约 178px）

| 正文框 | rows 7→3；`height: 76px`（原 176px） |

| 分隔行 | 「或手动填写以下信息」`display: none` |

## 历史对话面板配色改造（3 个 subagent 讨论后合成）

用户反馈面板**"颜色违和感有点重"**，截图里整个列表一片蓝。

### 根因：`--active` 语义错配（不是配色值写错）

`renderHistList` 原来按 `isPairRendered(id)` 决定是否加 `--active` —— 而它判断的是"**这条是否已渲染在聊天流里**"，聊天流默认就加载第一页，于是 **实测 10 条里 10 条全部命中**：

```
activeCount: 10 / totalItems: 10
每条: bg rgb(219,234,254) + qColor rgb(0,62,143) 加粗 + catBg rgb(239,241,244)
```

**把"实现细节"当"用户状态"来标记，是这次违和的根源**：强调色用在 100% 的条目上等于没有强调，只剩视觉噪音。另外 `:hover` 与 `--active` 用了完全相同的色值（`--zf-primary-light`），hover 时毫无反馈。

### 三个 subagent 的共识与分歧

开 3 个视角（色彩系统与对比度 / 列表状态语义 / 组件一致性），**三方独立收敛到"真因在 JS，CSS 只是降噪"**。它们提供的可采信增量：
- `.043` 这样的 hover 灰在 `#fafbfd` 底上只差 **10 个亮度单位**，肉眼几乎看不出（后来实测证实，我据此提到 `.08`）
- 灰标签压在蓝底上对比度仅约 **1.06:1**，是比"蓝字"更刺眼的脏点
- 项目**已有** `--zf-shadow-md` 浮层令牌，新面板自定义的重影比它重一倍
- 全站聚焦环统一用 `rgba(66,133,244,.16)`，新面板误写成 `.12`
- 滚动条改造**必须限定作用域**，写成裸 `::-webkit-scrollbar` 会吃掉全站滚动条

**但 subagent 的数值要复核**：有 agent 说 `.zf-badge` 圆角是"999/4px"，实际核实是 `border-radius: 999px`（纯胶囊）；另有 agent 建议分类标签改 `--zf-ink-3`，实测该色在 `--zf-muted` 上对比度不足 3:1，保留 `--zf-ink-2` 更稳。

```js
// renderHistList

```
注意 `rendered[]` 还有另一处用途（`followUp` 里筛"未渲染"条目），**只删 `isPairRendered` 函数，不要动 `rendered`**。

**CSS**：
| 项 | 改法 |
|---|---|
| 唯一强调 | `--current`：`background: rgba(66,133,244,.10)` + `box-shadow: inset 3px 0 0 var(--zf-primary)`（左蓝条用 inset 阴影，不占布局、文字不位移） |

### 【新坑】`scrollbar-width` 会屏蔽 `::-webkit-scrollbar`

实测 Chromium 153：一旦设置了 `scrollbar-width: thin`，同元素的 `::-webkit-scrollbar` 系列**不再被解析**（规范为避免两者歧义如此要求）。所以 `::-webkit-scrollbar { width: 8px }` 实际没生效，最终宽度由 `thin` 决定（约 10px）。**两者并存是给 Chrome 121 以前老内核的兜底，不是死代码**，别以为没生效就删掉。

### 等高的真正机制（本轮核心技术结论）
.zf-desk 是 grid，**两列同在 grid row 1**（实测 gridTemplateRows: 495.688px，
.zf-work 的 gridColumn/gridRow 都是 auto）。

- 左栏 align-self:stretch + height:100% 只让**左栏**拉伸；行高由左栏自己决定，
  右列仍只按内容高（457）→ 反而左栏比右栏高 39px
- **正解**：.zf-work { align-self: stretch }（对齐行高）+ 当前可见面板
  :not([hidden]) { flex: 1 1 auto } 吃掉剩余空间 → 两侧底边齐在 586
  （min-height:0 必须写，否则 flex item 不会缩到内容以下）
