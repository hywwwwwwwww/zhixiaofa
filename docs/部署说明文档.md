# 职小法 · 部署说明文档

> 环境：JDK 17+ ｜ Maven 3.8+ ｜ MySQL 8.0 ｜ Tomcat 9.0（javax.servlet）
> 打包产物：`target/zhixiaofa.war` ｜ 访问地址：`http://localhost:8080/zhixiaofa/`

---

## 一、环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 17 或以上 | `pom.xml` 中 `maven.compiler.release = 17`；在 JDK 21 上实测通过 |
| Maven | 3.8+ | 用于拉依赖与打包 WAR |
| MySQL | 8.0 | 需要 ngram 全文解析器（MySQL 5.7+ 内置），字符集 utf8mb4 |
| Tomcat | 9.0.x | 使用 `javax.servlet` 命名空间；若用 Tomcat 10+ 见第六节迁移说明 |

> **重要**：MySQL 的 Windows 版**不支持中文路径**。如果把解压目录或数据目录放在含中文的路径下，
> `mysqld` 会因为路径编码问题无法启动（basedir/datadir 解析失败）。
> 建议把 MySQL 安装目录与数据目录都放在纯 ASCII 路径下，例如 `D:/mysql`。

## 二、数据库准备

### 2.1 建库建表

```bash
mysql -u root -p < sql/schema.sql
```

脚本会创建数据库 `zhixiaofa`、15 张业务表、1 个统计视图，并在关键列上建立索引与全文索引。

### 2.2 导入测试数据

```bash
mysql -u root -p zhixiaofa < sql/data.sql
```

每张表不少于 10 条记录，脚本中已计算好密码摘要，可直接用以下账号登录：

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `admin123` | 管理员 |
| `zhangsan` / `lisi` / `wangwu` / `zhaoliu` … | `123456` | 普通用户 |

### 2.3 核对数据

```bash
mysql -u root -p zhixiaofa -e "
SELECT 'sys_user' t, COUNT(*) c FROM sys_user
UNION ALL SELECT 'law_article', COUNT(*) FROM law_article
UNION ALL SELECT 'qa_record',   COUNT(*) FROM qa_record
UNION ALL SELECT 'contract',    COUNT(*) FROM contract
UNION ALL SELECT 'doc_record',  COUNT(*) FROM doc_record;"
```

## 三、修改数据库连接配置

配置文件：`src/main/resources/db.properties`

```properties
jdbc.url=jdbc:mysql://127.0.0.1:3306/zhixiaofa?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
jdbc.username=root
jdbc.password=你的密码

# 连接池参数（自研连接池，全部可参数化）
pool.minIdle=2
pool.maxTotal=20
pool.maxWaitMillis=5000
pool.maxIdleMillis=300000
pool.validationQuery=SELECT 1

# 分页参数
page.defaultSize=10
page.maxSize=100
```

**支持 JVM 参数覆盖**，同一份 WAR 可以在不同库之间切换而不用重新打包：

```bash
-Djdbc.url=... -Djdbc.username=... -Djdbc.password=...
```

Tomcat 下写到 `bin/setenv.bat`（Windows）或 `bin/setenv.sh`（Linux）：

```bat
set "JAVA_HOME=C:\Program Files\Java\jdk-21"
set "CATALINA_OPTS=%CATALINA_OPTS% -Dfile.encoding=UTF-8"
set "CATALINA_OPTS=%CATALINA_OPTS% -Djdbc.url=jdbc:mysql://127.0.0.1:3307/zhixiaofa?useUnicode=true^&characterEncoding=utf8^&useSSL=false^&serverTimezone=Asia/Shanghai"
set "CATALINA_OPTS=%CATALINA_OPTS% -Djdbc.username=root -Djdbc.password=root"
```

## 四、编译与打包

### 4.1 仅编译

```bash
mvn clean compile
```

### 4.2 运行单元测试 + 生成覆盖率报告

```bash
mvn clean test
# 覆盖率报告：target/site/jacoco/index.html
```

### 4.3 打包 WAR

```bash
mvn clean package            # 含单元测试
mvn clean package -DskipTests  # 跳过测试
```

产物：`target/zhixiaofa.war`（约 8 MB，前端依赖已全部本地化，**零外部 CDN 依赖**）

> **踩坑提醒（JaCoCo 不出报告）**：`pom.xml` 里 surefire 的 `argLine` 必须写成
> `<argLine>@{argLine} -Dfile.encoding=UTF-8</argLine>`。
> 如果直接写死 `-Dfile.encoding=UTF-8`，会把 JaCoCo 注入的 `-javaagent` 参数覆盖掉，
> 导致不生成 `jacoco.exec`、覆盖率报告为空。
>
> **另一个坑（中文路径）**：如果项目路径含中文，JaCoCo 的 javaagent 参数在参数文件读写时会乱码，
> 同样导致数据落盘失败。本项目的做法是把 `jacoco.exec` 输出到纯 ASCII 路径
> （`pom.xml` 中 `<destFile>` / `<dataFile>`），Maven 本地仓库也放在 `D:/zhixiaofa-dev/m2repo`。

## 五、部署到 Tomcat

### 5.1 部署

```bash
# 拷贝 WAR 到 Tomcat
cp target/zhixiaofa.war $CATALINA_HOME/webapps/zhixiaofa.war

# 启动
$CATALINA_HOME/bin/startup.sh      # Linux / macOS
%CATALINA_HOME%\bin\startup.bat    # Windows
```

Tomcat 会自动解压为 `webapps/zhixiaofa/`。访问：

- 入口页：`http://localhost:8080/zhixiaofa/`（自动判断登录态并跳转）
- 登录页：`http://localhost:8080/zhixiaofa/login.html`
- 后台看板：`http://localhost:8080/zhixiaofa/admin/index.html`（需管理员登录）

### 5.2 日志

- 业务日志：`$CATALINA_HOME/logs/zhixiaofa.log`（按天滚动，保留 30 天，单文件上限 200MB）
- 控制台日志：`$CATALINA_HOME/logs/catalina.out`
- 日志级别：项目包 `com.zhixiaofa` 为 DEBUG，第三方框架为 WARN（见 `logback.xml`）

### 5.3 验证清单

```bash
# 1) 匿名访问受限接口应返回 401 + 业务码 11301
curl -i http://localhost:8080/zhixiaofa/api/users

# 2) 登录
curl -c cookie.txt -X POST http://localhost:8080/zhixiaofa/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'

# 3) 带会话访问
curl -b cookie.txt http://localhost:8080/zhixiaofa/api/admin/stats/overview

# 4) 法条全文检索
curl "http://localhost:8080/zhixiaofa/api/law-articles?keyword=%E8%AF%95%E7%94%A8%E6%9C%9F"
```

### 5.4 停止与重新部署

```bash
$CATALINA_HOME/bin/shutdown.sh
# 重新部署前先删掉解压目录，避免旧文件残留
rm -rf $CATALINA_HOME/webapps/zhixiaofa $CATALINA_HOME/webapps/zhixiaofa.war
cp target/zhixiaofa.war $CATALINA_HOME/webapps/
$CATALINA_HOME/bin/startup.sh
```

## 六、常见问题

| 现象 | 原因与解决 |
|---|---|
| 启动报 `未找到数据库配置文件 db.properties` | `src/main/resources/db.properties` 未被编译进 `WEB-INF/classes`，执行 `mvn clean package` 重新打包 |
| 所有接口返回 `10401 数据库操作失败` | 检查 `db.properties` 的 url/账号/密码；确认 MySQL 已启动、`zhixiaofa` 库已建 |
| 启动报连接池初始化失败 | MySQL 驱动未打入 WAR，检查 `mysql-connector-j` 依赖是否被 `provided` 掉 |
| 中文检索查不到结果 | 建表时未使用 `WITH PARSER ngram`；MySQL 默认分词器不切中文，需重建全文索引 |
| 参数全是 null | 前端未带 `Content-Type: application/json`，`JsonBodyFilter` 不会包装请求；或用了不支持 JSON 的老版本 |
| 页面样式错乱 | 未通过 HTTP 服务器访问（直接双击 html 会导致 `/api` 与静态资源路径错误），必须经 Tomcat 访问 |
| JaCoCo 报告为空 | 见第四节的两个坑（`@{argLine}` 与 ASCII 路径） |
| 端口被占用 | 本机已有 MySQL/Tomcat 在跑；换端口并同步修改 `db.properties` 或 Tomcat 的 `server.xml` |

### 迁移到 Tomcat 10+（jakarta.servlet）

Tomcat 10 起 Servlet API 命名空间由 `javax.servlet` 改为 `jakarta.servlet`，迁移步骤：

1. `pom.xml` 中依赖改为 `jakarta.servlet:jakarta.servlet-api:6.0.0`（`provided`）；
2. 全局替换源码中的 `javax.servlet` → `jakarta.servlet`（`filter` 与 `servlet` 两个包）；
3. `web.xml` 的 `xsi:schemaLocation` 与 `version` 改为 6.0 对应的 schema。

## 七、性能优化记录（课程要求：修复至少 3 个性能瓶颈）

| # | 瓶颈 | 优化前 | 优化措施 | 优化后 |
|---|---|---|---|---|
| 1 | 法条/文章关键词检索 | `LIKE '%关键词%'` 无法使用索引，全表扫描 | 改建 ngram 全文索引，改用 `MATCH ... AGAINST` | 命中行数从全表扫描降为按索引召回（实测「试用期」直接命中 4 条法条 / 2 篇文章） |
| 2 | 数据库连接频繁创建销毁 | 每次查询 `DriverManager.getConnection()` | 自研连接池，复用物理连接 + 动态代理归还 | 连接创建次数由「每请求 1 次」降为「池内预热 2 个 + 按需扩容」，避免了 TCP 握手与 MySQL 认证开销 |
| 3 | 写操作日志阻塞响应 | 同步 `INSERT` 日志表 | 有界队列 + 单线程消费者异步落库，队列满则丢弃 | 日志写入不再占用用户请求耗时，接口平均耗时下降（见 `/api/admin/logs/stats` 的 `slow` 数据） |
| 4 | 列表页 N+1 查询 | 先查列表再逐条查关联对象 | 用 `LEFT JOIN` 在一条 SQL 内带出关联字段（如问答列表带提问人昵称） | 后台列表页由 1+N 次查询降为 1 次 |
| 5 | 前台文章列表排序 | `ORDER BY published_at DESC` 触发 filesort | 建组合索引 `(status, published_at)` | 索引天然有序，配合 `LIMIT` 提前终止，消除 filesort |
| 6 | 分页参数滥用 | 用户可传 `pageSize=999999` 拖垮数据库 | `page.maxSize` 配置上限，Service 层强制钳制 | 单页最多 100 条 |
