### 2.3 单元测试中发现并修复的真实缺陷

单元测试不只用来「跑通」，本次通过测试暴露并修复了 3 个真实问题：

| # | 问题 | 发现方式 | 修复 |
|---|---|---|---|
| 1 | **全文检索参数顺序错乱**：`SqlBuilder.with(kw, offset, limit)` 把条件参数排在关键词前面，与 SQL 中占位符顺序不一致，导致带关键词检索恒返回 0 条 | `SqlBuilderTest.mixedConditionOrder` 断言参数顺序 | 新增 `SqlBuilder.andMatch(columns, keyword)`，把关键词作为第一个参数入列；并补充「`MATCH` 不应在关键词为空时生成」的断言 |
| 2 | **关联字段映射列名错误**：`MAPPER_WITH_USER` 读取 `nickname`，而 SQL 别名是 `user_nickname`，后台问答列表直接报 `Column 'nickname' not found` | 接口联调测试 | 修正生成器中的列名，与 SQL 别名对齐 |
| 3 | **问答分类被泛化词抢走**：「签了竞业协议但没有补偿」同时含「竞业」与「补偿」，因「补偿」属「解除终止」且该分类在前，被误判为解除终止 | `QaServiceImplTest.inferCategory` | 重排分类关键词优先级（具体分类前置），并把过于泛化的「补偿」收窄为「经济补偿」 |

### 2.4 覆盖率不足的地方与改进方向

- `util` 包 30%：`SimpleConnectionPool` 的借出/归还/超时/校验分支需要真实连接才能覆盖，
  建议补充集成测试（用 H2 或真实 MySQL 的单元测试库）覆盖借还路径；
- `dao.impl` 6%：DAO 是 SQL 适配层，改进方向是用 Testcontainers 起临时 MySQL 做 DAO 集成测试；
- `servlet` 0%：建议补充基于 Mockito 的 `HttpServletRequest/Response` 打桩测试，
  覆盖 `BaseServlet` 的异常映射与 `pathSegments` 解析。

## 四、性能测试（JMeter 参考方案）

课程要求「使用 JMeter 模拟 100 并发用户」。本项目的自研连接池已把最大连接数参数化为
`pool.maxTotal`（默认 20），压测前可按机器配置调整。建议的压测场景：

| 场景 | 线程数 | 循环 | 目标接口 | 关注指标 |
|---|---|---|---|---|
| 读密集 | 100 | 20 | `GET /api/law-articles?keyword=试用期` | 平均响应时间、90% 线、错误率 |
| 写密集 | 100 | 10 | `POST /api/qa` | 事务成功率、连接池等待 |
| 混合 | 100 | 20 | 登录 + 问答 + 收藏 | 吞吐量 TPS |
| 后台统计 | 50 | 10 | `GET /api/admin/stats/overview` | 聚合查询耗时 |

**压测时需要关注的连接池指标**：通过 `GET /api/admin/stats/pool` 实时观察
`created`（已创建连接数）、`idle`（空闲）、`borrowed`（借出）。
若 `borrowed` 持续等于 `maxTotal` 且出现「获取数据库连接超时」，
说明池太小，应调大 `pool.maxTotal`；若 `created` 远大于 `borrowed`，说明池过大浪费资源。

**已完成的优化**（详见《部署说明文档》第七节）：

1. 全文索引替代 `LIKE '%kw%'` 全表扫描；
2. 自研连接池复用物理连接，消除每次请求的连接创建开销；
3. 操作日志异步落库，不阻塞业务响应；
4. `LEFT JOIN` 消除列表页 N+1 查询；
5. 组合索引消除文章列表的 filesort；
6. `pageSize` 上限钳制，防止恶意的超大分页拖垮数据库。

## 六、测试结论

1. **功能完整性**：课程的「数据增删改查」要求已在 15 张表、13 个 Servlet、70+ 个接口上完整落地，
   50 项端到端用例全部通过。
2. **业务逻辑正确性**：Service 层 155 项单元测试全部通过，行覆盖率 72.0%，高于 60% 的要求。
3. **健壮性**：参数校验、权限校验、事务回滚、异常统一处理均已验证；
   越权访问（普通用户调用管理员接口）与数据越权（查看他人合同/文书）都被正确拦截。
4. **可部署性**：WAR 包在 Tomcat 9 + MySQL 8.0 环境实测部署成功，
   全部页面与静态资源可访问，零外部 CDN 依赖。
5. **待改进项**：DAO 层与 Servlet 层的单元测试覆盖率偏低（适配层特性所致），
   建议后续引入 Testcontainers 与 Servlet API 打桩补齐；压测需在真实 JMeter 环境按第四节方案执行。
